Changes made during migration:

- Removed the remaining direct Lovable AI dependency from `translate-content`.
- `translate-content` now uses `AI_API_KEY`, optional `AI_API_URL`, and optional `AI_MODEL`, and verifies staff access through `public.is_staff`.

- No `lovable.dev`, `LOVABLE_API_KEY`, or `LOVABLE_SEND_URL` references remain in this Supabase bundle.

Static TypeScript syntax check: 20/20 entrypoints passed.

1. `restore_edge_function_support_tables`

2. `align_email_logs_for_edge_functions`
   - restores `email_logs.metadata`

   - RPC execution is restricted to `service_role`

## Cron

The historical migrations contain one previous cron:

- `visa-document-reminders-daily` — `0 9 * * *`

That old migration points to the retired project URL and hard-codes its old anon JWT, so it must NOT be replayed as-is.

No historical migration was found for the marketing queue cron. A new production schedule should be added only after the corresponding Edge Functions have been deployed:

- `visa-document-reminders-daily`: daily at 09:00 UTC
- `process-marketing-queue-every-minute`: once per minute

Both should call the production project URL and authenticate using the Vault `edge_cron_secret` header rather than embedding a Supabase API key in SQL.

## Secrets still required before full production cutover

Supabase automatically supplies its own project URL/API credentials to hosted Edge Functions. Do not duplicate those manually.

External/application secrets still need to be confirmed in Edge Function Secrets:

- `RECAPTCHA_SECRET_KEY` — required by the public contact form and reCAPTCHA endpoint
- `AI_API_KEY` — required by `translate-content`
- `AI_API_URL` — optional; direct Gemini OpenAI-compatible endpoint is the default
- `AI_MODEL` — optional; `gemini-2.5-flash` is the default
- `OCR_API_URL` — required if automatic passport OCR is to remain enabled
- `OCR_API_KEY` — if the configured OCR provider requires it
- `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` — only if web push notifications are used

SMTP itself is already stored in `public.email_settings` and was verified as active and complete in `lejapon-prod`.
